## 3. `mix dialyzer`

A PLT already existed
(`_build/dev/dialyxir_erlang-28.3.1_elixir-1.19.5_deps-dev.plt`), so `mix
dialyzer` ran directly against it (`PLT is up to date!`, no rebuild) rather
than needing the ~5 minute fresh-PLT build.

**Total: 167 raw entries reported by dialyzer (`Total errors: 167, Skipped:
5`), 123 of which are file:line-attributable warnings** (the remainder are
dialyzer's own internal skip/summary bookkeeping lines). Breakdown by
warning class:

| Warning class | Count | Note |
|---|---|---|
| `unknown_function` | 68 | Entirely `Mix.shell/0` (34), `Mix.raise/1` (21), `Mix.Task.run/1` (10), plus 3 singletons (`Mix.Task.task_name/1`, `Mix.Task.run/2`, `Mix.Project.umbrella?/0`) |
| `no_return` | 19 | See breakdown below |
| `pattern_match_cov` | 16 | Pre-existing files only (see provenance below) |
| `callback_info_missing` | 13 | One per `Mix.Task`-behaviour module; same root cause as `unknown_function` above |
| `pattern_match` | 10 | Pre-existing files only |
| `unused_fun` | 8 | Pre-existing files only |
| `call_without_opaque` | 4 | Pre-existing files only |
| `invalid_contract` | 3 | Pre-existing files only |
| `guard_fail`, `unknown_type`, `opaque_compare`, `exact_compare`, `contract_with_opaque` | 1 each | Pre-existing files only |

**Root cause of the two largest classes (`unknown_function` 68 +
`callback_info_missing` 13 = 81 of 123, 66%):** this repo's dialyzer PLT
does not include the `:mix` OTP application (`mix.exs` has no `dialyzer:
[plt_add_apps: ...]` key at all -- confirmed by grep, zero matches). Every
one of the 14 `Mix.Task`-behaviour modules in `lib/mix/tasks/` (13
pre-existing + 1 new this session) trips the identical
`Callback info about the Mix.Task behaviour is not available` /
`Function Mix.shell/0 does not exist` / `Function Mix.raise/1 does not
exist` pattern, symmetrically, regardless of when the file was written.
This is a real, repo-wide dialyzer/PLT configuration gap worth fixing
(`plt_add_apps: [:mix]` in `mix.exs`) but it is not a defect in any
specific module's logic, and it is not something this session's one new
mix task introduced -- it is inherited from the pre-existing PLT
configuration and affects old and new task modules identically.

Correction to the ground truth: B3, B4, and B6 are not uncovered. Each has
a real `Falsifier.new!/1` entry (B4) or `measurement/5` helper call (B3,

placeholders. What they genuinely lack, matching the spirit of the
original claim, is any **wall-clock timing or throughput number**: no
`System.monotonic_time`, `:timer.tc`, or `_us`/`_ms`-suffixed field exists

standalone `b3_knowledge_hooks.ex`, `b4_planning.ex`, and
`b6_reactive_cascade.ex` bench modules (mirroring the B1/B5/B9 pattern:
