# A2A-2607: close Blue River Dam as the cross-repo control plane

- **Status**: OPEN
- **Severity**: Critical
- **Standing**: `PARTIAL_ALIVE`
- **Owning repos**: `seanchatmangpt/ggen`, `seanchatmangpt/ash_a2a`, `seanchatmangpt/unrdf`, `seanchatmangpt/affidavit`

## Problem

Blue River Dam already exists as ontology, generated Rust, lifecycle gates, benchmarks, receipts and authority-oriented control structures. The remaining gap is that the new DME topology is not yet one admitted path spanning semantic law, routing, local/idle compute, authority, DO, receipt, and standing.

The Dam must become the upstream flow controller rather than another orchestrator that interprets downstream artifacts.

## Required change

Create a single cross-repo contract in which Blue River Dam receives only admitted semantic objects and can SELECT among lawful execution substrates without gaining consequence authority itself.

Target topology:

`O -> O* -> classify -> CMCA -> {deterministic | SHLLM | idle estate | frontier} -> candidate result -> admission -> construct -> authority -> BRCE/DO -> receipt -> standing`

## Laws

1. Model/provider identity is downstream of capability identity.
2. Dam route selection cannot bypass semantic admission or CommandBus.
3. No execution substrate may mint authority.
4. Every route has an explicit consequence class and receipt obligation.
5. UNKNOWN remains visible when no admitted route closes it.
6. Same admitted state + same policy profile yields the same route decision.

## Chicago falsifiers

1. Replacing the frontier model provider cannot change authority or consequence class.
2. A deterministic-known request never reaches frontier inference.
3. A route with no standing capability is refused.
4. A successful substrate result without admission cannot reach DO.
5. Every consequence-bearing route terminates in a durable/pending receipt state.

## Definition of done

- one machine-readable cross-repo contract defines the flow;
- each repo exposes a typed seam rather than prose integration instructions;
- one end-to-end repository-native fixture proves the full path and all negative fences;
- evidence is separated into exact-head source, local execution, hosted CI, runtime standing, merge and publication.
