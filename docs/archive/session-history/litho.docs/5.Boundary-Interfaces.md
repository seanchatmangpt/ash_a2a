# System Boundary Interface Documentation

This document describes the system's external invocation interfaces, including CLI commands, API endpoints, configuration parameters, and other boundary mechanisms.

## Command Line Interface (CLI)

### hddl_cli <domain_file> <problem_file>

**Description**: Standalone Rust binary (native/hddl_cli) that wraps the ferroplan FOND HTN solver. It reads the HDDL domain and problem files from disk, invokes ferroplan::solve_hddl, and prints the resulting UniversalPlan serialized as JSON to stdout on success. On any failure (missing files, HDDL parse/ground/translate/solve errors), it prints a JSON error object to stdout and exits with code 1. This is the sole integration surface between the Elixir system and the native planner, invoked as a subprocess rather than an in-process NIF.

**Source File**: `/Users/sac/ash_a2a/native/hddl_cli/src/main.rs`

**Arguments**:

- `domain_file (argv[1])` (file path (string)): required - Path to the HDDL domain definition file consumed by the ferroplan solver.
- `problem_file (argv[2])` (file path (string)): required - Path to the HDDL problem instance file consumed by the ferroplan solver.

**Usage Examples**:

```bash
hddl_cli domain.hddl problem.hddl
```

```bash
hddl_cli /path/to/domain.hddl /path/to/problem.hddl > plan.json  # exit code 0 on success, 1 on failure
```

### application boot (AshA2A.Application.start/2)

**Description**: Startup configuration interface of the library. The application entry point reads the supervision configuration from the application environment, starts A2A.AgentSupervisor children for every configured agent, launches the default replay receipt store (replaceable by a custom AshA2A.ReceiptStore implementation), and attaches telemetry forwarding (OCEL forwarder). Host applications interact with the system primarily through these application-env keys plus the MIX_ENV environment variable.

**Source File**: `/Users/sac/ash_a2a/lib/ash_a2a/application.ex; /Users/sac/ash_a2a/config/config.exs; /Users/sac/ash_a2a/lib/ash_a2a/llm_profiles.ex`

**Options**:

- `config :ash_a2a, :agents`(keyword list of agent specs): optional - List of agent configuration entries; each compiled agent becomes a supervised A2A GenServer in the host supervision tree.
- `config :ash_a2a, :llm_profiles`(keyword list mapping role atoms to model specs): optional - Maps abstract LLM role atoms (e.g. :semantic_reasoner) to concrete req_llm/ash_ai model specs and call options. Resolved at runtime by AshA2A.LLMProfiles.resolve/1; switching model providers is a pure config change. (default: `none (resolve/1 returns {:error, :unknown_role} for unconfigured roles)`)
- `config :ash, :default_string_length_count`(atom): optional - Global Ash framework default set in config/config.exs; string length validations count Unicode codepoints. (default: `:codepoints`)
- `MIX_ENV`(environment variable (atom)): optional - Environment variable read by config/config.exs via config_env(); when set to test, config/test.exs overrides are imported. (default: `dev`)

**Usage Examples**:

```bash
config :ash_a2a, :agents, [my_app: [resources: [MyApp.Resource]]]
```

```bash
config :ash_a2a, :llm_profiles, semantic_reasoner: [model: "openai:gpt-4o", options: [temperature: 0]]
```

```bash
MIX_ENV=test mix test
```

## API Interfaces

### GET (discovery retrieval; wire transport delegated to host application) AgentCard discovery document (per configured agent)

**Description**: Each configured agent exposes an A2A-compliant AgentCard discovery document compiled deterministically from public Ash resource actions by the CapabilityIndex.AgentCardBuilder. The card lists skills, argument schemas introspected from real actions, tags, and descriptions. Fail-closed validation guarantees the advertised card matches dispatchable behavior: overrides may describe or suppress capabilities but never invent them.

**Source File**: `/Users/sac/ash_a2a/lib/ash_a2a/capability_index/agent_card_builder.ex (built via lib/ash_a2a/capability_index/compiler.ex, supervised from lib/ash_a2a/agent.ex)`

**Response Format**: JSON AgentCard (A2A protocol discovery document: agent skills, input/output schemas, tags, capabilities)

**Authentication**: None enforced at the discovery layer by the framework; access control of the published card is delegated to the host transport.

### A2A protocol message send (protocol-level operation; transport plumbing delegated to host) A2A.Message ingress (agent task/message submission)

**Description**: External A2A clients and peer agents submit A2A.Message structs to a supervised agent GenServer. Inbound messages flow through the Dispatcher into the trust-boundary ContextResolver (which strips untrusted message metadata and constructs an ExecutionContext from Identity and Authority), then onto the receipted CommandBus for idempotent, replay-safe invocation of real Ash actions. Consequence-bearing executions persist receipts; replies follow the A2A task lifecycle.

**Source File**: `/Users/sac/ash_a2a/lib/ash_a2a/dispatcher.ex (dispatch chain: dispatcher -> context_resolver -> command_bus; lifecycle in lib/ash_a2a/task_lifecycle.ex)`

**Request Format**: A2A.Message struct (JSON-serializable A2A protocol envelope with message parts and metadata)

**Response Format**: A2A reply / task lifecycle events referencing receipted command execution results (RuntimeReceipt); JSON-serializable

**Authentication**: Trust-boundary resolution at dispatch: raw message metadata is treated as untrusted evidence; caller identity and authority are resolved via AshA2A.Identity and AshA2A.Authority inside the ContextResolver before any domain action is invoked.

## Integration Suggestions

### subprocess_invocation

Invoke the native HDDL planner as a subprocess from the semantic planning pipeline (planning_ir.ex feeds hddl_cli). The CLI contract is: argv[1] = domain file path, argv[2] = problem file path; JSON UniversalPlan on stdout with exit code 0 on success, JSON error object with exit code 1 on any failure. Always check the exit code before parsing stdout, and treat both success and error payloads as JSON.

**Example Code**:

```
case System.cmd("hddl_cli", [domain_path, problem_path], stderr_to_stdout: false) do
  {output, 0} ->
    {:ok, plan} = Jason.decode(output)  # UniversalPlan JSON
  {output, 1} ->
    {:error, reason} = Jason.decode(output)  # structured JSON error object
end
```

**Best Practices**:

- Pin the ferroplan dependency to the exact commit used by beam4pm's submodule (as done in native/hddl_cli/Cargo.toml) for reproducible planner behavior
- Write domain/problem to temp files with cleanup to avoid leaking planning inputs
- Treat the emitted plan as candidate-only evidence: it never carries execution authority and must pass admission gates
- Route failures (exit code 1) into the semantic feedback loop for replanning

### application_configuration

Embed the framework in a host Elixir/Ash application by declaring agents under `config :ash_a2a, :agents`. AshA2A.Application.start/2 reads this key and launches one supervised A2A GenServer per agent plus the default replay receipt store. Hosts may replace the :receipt_store child with any AshA2A.ReceiptStore implementation (e.g. the EKV-backed durable store) that owns its own supervision.

**Example Code**:

```
# config/config.exs
config :ash_a2a, :agents,
  my_app: [resources: [MyApp.Tickets, MyApp.Orders]]

# children in your application.ex
{AshA2A.ReceiptStore.EKV, name: AshA2A.ReceiptStore} # replaces the default store
```

**Best Practices**:

- Keep agent definitions in application config so the supervision tree is environment-aware
- Use the EKV receipt store in production for receipts that survive process and node restarts
- Run `mix ash_a2a.verify_architecture` in CI to guarantee AgentCard/dispatch alignment

### llm_provider_configuration

Configure LLM provider bindings purely through `config :ash_a2a, :llm_profiles`. Ash actions declare abstract roles (e.g. :semantic_reasoner); AshA2A.LLMProfiles.resolve/1 maps each role to a req_llm model spec plus call options. Capability semantics are sealed from provider identity (A2ACapabilityIdentity != ModelProviderIdentity), so switching providers requires no code changes.

**Example Code**:

```
config :ash_a2a, :llm_profiles,
  semantic_reasoner: [model: "anthropic:claude-sonnet-4-20250514", options: [temperature: 0]]

# runtime resolution
{:ok, profile} = AshA2A.LLMProfiles.resolve(:semantic_reasoner)
```

**Best Practices**:

- Use temperature 0 for deterministic semantic extraction and planning proposals
- Remember all LLM output is untrusted evidence: candidates are re-validated fail-closed before admission
- Validate profiles at boot so unknown roles fail fast instead of at call time

### delivery_and_execution_adapters

Optionally plug in durable delivery and remote execution backends: Oban as the delivery adapter (lib/ash_a2a/delivery/oban.ex) for queued command dispatch, and FLAME as the execution adapter (lib/ash_a2a/execution/flame.ex) to run command execution off the host node. Both funnel through the same receipted CommandBus, preserving idempotency and replay guarantees.

**Example Code**:

```
# Oban queues for A2A command delivery
config :my_app, Oban,
  queues: [ash_a2a_delivery: 10]

# FLAME pool for elastic remote execution of dispatched commands
```

**Best Practices**:

- Enable Oban delivery when commands must survive node crashes
- Use FLAME for compute-heavy semantic synthesis to keep the agent node responsive
- Ensure receipt stores are durable (EKV) whenever durable delivery is enabled, so receipts and jobs stay consistent

### semantic_interoperability

Align projected ontologies with public standards instead of inventing terms. AshA2A.Semantic.Vocabulary.prefixes/0 registers canonical namespaces (rdf, rdfs, owl, prov, time, odrl, skos, schema) used when the Ontology materializes triples (priv/ggen/ash_a2a/ontology.ttl, queried via spec.rq). Downstream triple stores and SPARQL consumers can rely on these standard prefixes.

**Example Code**:

```
AshA2A.Semantic.Vocabulary.prefixes()
# => %{"rdf" => "http://www.w3.org/1999/02/22-rdf-syntax-ns#", "prov" => "http://www.w3.org/ns/prov#", ...}
```

**Best Practices**:

- Extend projections using existing prior-art terms before coining new ones
- Publish the generated ontology.ttl alongside the AgentCard for semantic-capable A2A peers
- Use PROV terms for receipt provenance to make replay audits interoperable

### environment_configuration

Use MIX_ENV-driven configuration for environment separation. config/config.exs bootstraps global Ash defaults (default_string_length_count: :codepoints) and imports config/test.exs when config_env() == :test. All runtime configuration for the framework flows through this Mix config bootstrap.

**Example Code**:

```
# config/config.exs
config :ash, default_string_length_count: :codepoints

if config_env() == :test do
  import_config "test.exs"
end
```

**Best Practices**:

- Keep test-only overrides (e.g. in-memory receipt store, fake LLM profiles) in config/test.exs
- Inject fake LLM clients in tests rather than switching providers via llm_profiles
- Count strings in codepoints consistently to avoid validation drift across environments
