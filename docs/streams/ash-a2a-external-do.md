# ash_a2a External-Do Consequence Override

Stream `ash-a2a-format` (side finding for ggen_igniter's external-do stream). Question: does
ash_a2a's DSL or installer allow an action-level `consequence` and/or `authority` declaration
for an `:external_do` capability? Base `2730c9b`. Every claim below cites file:line in this tree;
the PR #27 head `8d61f46` is byte-identical for the four files cited in the first table
(`git diff` of `dsl.ex`, `skill.ex`, `capability_index/compiler.ex`, `mix/tasks/ash_a2a.install.ex`
between `8d61f46` and `2730c9b` is empty).

## Answer

| Question | Result | Status |
|---|---|---|
| Action-level `consequence:` in the DSL | Yes: `skill` entity option | ALIVE (read back) |
| Value set | `:observe`, `:change`, `:external_do`, `:unknown` | ALIVE (schema read back) |
| Action-level `authority:` (grant) declaration in the DSL | No such key | ALIVE (schema) |
| Installer emits a `skill ... consequence:` entry | No | INSPECTED (source) |
| Installer on an existing `a2a` block | Adds a second, empty starter block; existing skill survives | ALIVE (executed) |

ALIVE here means observed execution of the exact subject: `MIX_ENV=test mix run` printed the
values below from real compiled fixtures and from `AshA2A.Dsl`'s own entity schema.

## DSL evidence

- `lib/ash_a2a/dsl.ex:46-56` declares `consequence: [type: {:one_of, [:observe, :change,
  :external_do, :unknown]}, required: false]` on the `skill` entity schema.
- `lib/ash_a2a/dsl.ex:122-127` gives the entity its arguments: `[:name, {:optional, :resource},
  :action]`, so the call shape is `skill :name, :action, consequence: :external_do` inside an
  `a2a do ... end` block on a resource, or `skill :name, Resource, :action, consequence: ...` on
  a domain.
- Observed entity schema keys: `[:name, :resource, :action, :description, :tags, :expose?,
  :consequence, :on_cancel]`. `:authority` is not among them. The `a2a` section itself only
  takes `semantic_requests` (`lib/ash_a2a/dsl.ex:159` exposes the section list).
- Real fixture readback (`lib/ash_a2a/chicago/fixtures/authority.ex:111,141` declare
  `skill(:actuate, :actuate, consequence: :external_do)`):

```text
AshA2A.Chicago.Fixtures.Authority.Probe.actuate: consequence=:external_do
AshA2A.Chicago.Fixtures.Authority.Probe.mutate: consequence=:change
AshA2A.Chicago.Fixtures.Authority.Probe.peek: consequence=:observe
AshA2A.Chicago.Fixtures.Authority.Vault.actuate: consequence=:external_do
```

## How the override is resolved

- `lib/ash_a2a/capability_index/compiler.ex:64` computes
  `override_value(override, :consequence, default_consequence(action.type))`.
- `lib/ash_a2a/capability_index/compiler.ex:162-166`: `:read` is `:observe`;
  `:create`/`:update`/`:destroy` are `:change`; any generic action is `:unknown`.
- `lib/ash_a2a/capability_index/compiler.ex:168-169`: the override wins over the default
  (`Map.get(override, field) || default`); an unset override falls back to the default.
- No validator or transformer touches `consequence` (`grep consequence` over
  `capability_index/validator.ex`, `transformers/build_capability_index.ex` and `info.ex`
  returns nothing), so an override is not cross-checked against the action type.
- `lib/ash_a2a/capability_index/compiler.ex:30-31`: capability id is
  `"#{inspect(resource)}.#{action}"`.

## What an unclassified generic action does

A generated generic action with no override is `:unknown` and fails closed at dispatch:

- `lib/ash_a2a/agent.ex:503-504` returns `%{code: :consequence_unclassified, ...}`.
- `lib/ash_a2a/command_bus.ex:683` refuses `:unknown` with `consequence_unclassified`.
- `:change` and `:external_do` both route through `AshA2A.CommandBus`
  (`lib/ash_a2a/agent.ex:492,524`) and require an authority
  (`lib/ash_a2a/command_bus.ex:679-681` refuses with `authority_required` when none is present).

## Authority is runtime, not DSL

- `lib/ash_a2a/authority/grant.ex:89` sets the default policy `:broker`; `config/test.exs:57-58`
  selects `:broker` with `AshA2A.Authority.Broker.InMemory`.
- A grant is keyed on `(principal, capability_id)`: `lib/ash_a2a/authority/grant.ex:203`
  (`grant/3`), `lib/ash_a2a/authority/grant.ex:117` (`authorize/3`).
- So an `:external_do` capability generated by ggen_igniter is declared once (the `consequence:`
  override) and granted separately at runtime by capability id. There is no DSL slot for the
  grant.
- Envelope-level consequence is cross-checked against the DSL attestation:
  `lib/ash_a2a/chicago/courts/authority_non_implication.ex:251` records that a request declaring
  `observe` while the DSL attests `external_do` is not admitted.

## Installer behavior

`lib/mix/tasks/ash_a2a.install.ex` (Igniter task, defined only when `Igniter` is loaded):

- `:71-76` adds the `{:a2a, "~> 0.2"}` dependency and the `AshA2A.Formatter` plugin.
- `:139-146` merges `AshA2A` into `extensions:` via `Spark.Igniter.add_extension/5`
  (idempotent, covered by `test/mix/tasks/ash_a2a_install_test.exs:84-116`).
- `:156-174` inserts an empty `a2a do end` block after the target's `use` call. It never emits a
  `skill` entry and never mentions `consequence`.
- `:87-101` (no `--target`): only a notice; no module is patched.
- The starter block is not idempotent. `test/mix/tasks/ash_a2a_install_test.exs:110-112` states
  that duplication of the starter `a2a do end` block on a second run is a known, pre-existing
  concern, and the `add_code` at `:161-168` is unconditional. ALIVE (executed by the qualifier
  of this stream, not by the builder): a real in-memory Igniter project
  (`Igniter.Test.test_project/1`, `Igniter.compose_task("ash_a2a.install", ["--target",
  "Test.Resource"])`) produced two consecutive empty `a2a do end` blocks after two runs, and,
  against a module that already held `a2a do skill(:actuate, :actuate, consequence:
  :external_do) end`, prepended a second, empty `a2a do end` in front of it (two `a2a do`
  occurrences either way). The duplicate is cosmetic: a module compiled with both blocks yields
  `Spark.Dsl.Extension.get_entities(mod, [:a2a])` equal to `[actuate: :external_do]` and the
  persisted `:ash_a2a_skill_overrides` still carries `consequence: :external_do`, so the skill
  and its consequence survive.
- Classification read back for a generic action, executed: `skill(:with_override,
  :with_override, consequence: :external_do)` gives `consequence: :external_do`, id
  `ExtX.Resource.with_override`; the same kind of action with no `skill` entry gives
  `consequence: :unknown`, id `ExtX.Resource.without_override`.

## Consequence for the ggen_igniter external-do stream

1. Emit the override from the ontology: a generated `a2a` block containing
   `skill(:action_name, :action_name, consequence: :external_do)` per external-effect action.
   Nothing else in ash_a2a produces it.
2. Own the whole `a2a` block in the template, or run the template after the installer and
   replace the starter block, so a second `a2a do end` is not left behind.
3. Do not model authority as DSL. Model it as a runtime grant keyed by capability id
   `"<Resource>.<action>"` (the id the compiler computes at `compiler.ex:30-31`).
4. Falsifier to add (read from the code paths above, not yet executed for a generated action):
   an `:external_do` action generated without the override dispatches as
   `consequence_unclassified`; the same action with the override dispatches as
   `authority_required` until a broker grant exists.
